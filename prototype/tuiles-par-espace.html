Tuiles par espace

La grille de tuiles d'Arc, rattachée à l'espace plutôt qu'au navigateur. Une tuile porte deux champs indépendants : où elle est visible, et quelle identité elle utilise. C'est ce qui permet à Gmail d'ouvrir deux comptes selon l'espace, pendant que Zotero n'en ouvre qu'un seul partout.

    Défaut : héritée. C'est ce qui distingue Nash. Fixée est un choix explicite, pour les sites dont le compte est unique par nature.

    Règles démontrées

    • 01
      La grille appartient à l'espace

      Changer d'espace change la grille, la teinte et le container. Dans Anime, plus d'Outlook.

    • 02
      Visibilité et identité sont deux champs

      Où la tuile se voit, et quelle session elle ouvre, sont des questions séparées.

    • 03
      L'espace porte le container

      Par défaut, une tuile s'instancie dans le pot à cookies de l'espace courant.

    • 04
      L'identité se demande une fois

      Pas dans un panneau de réglages : au moment où la tuile s'ouvre dans un second espace.

    • 05
      La ligne globale est plafonnée à 4

      La contrainte est la fonctionnalité : sans plafond, elle redevient le fourre-tout d'Arc.

    • 06
      Une clé, une instance

      Un second clic revient à l'onglet existant. Jamais de doublon, jamais de perte d'état.

    Modèle

    Tuile {
  id, url, titre
  icone      : { source, cache: local }
  visibilite : "globale" | spaceId
  identite   : "heritee" | { fixee: containerId }
  ordre
}

Espace {
  id, nom, emoji, teinte
  container : contextualIdentity
}

instance(tuile, espace) =
  "heritee"  -> (tuile.id, espace.container)
  { fixee }  -> (tuile.id, fixee)

    Non simulé ici : le rendu des pages, la persistance après redémarrage, et le retour d'une tuile vers son URL d'origine quand on navigue ailleurs depuis elle. Le reste — visibilité, identité, plafond, clé d'instance, icône — correspond à ce qui serait implémenté dans la couche chrome de Gecko, sans toucher au moteur.
